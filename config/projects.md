- **Key features:** end-to-end RAG — query rewriting → embedding → pgvector retrieval → confidence validation → token-budgeted context → grounded generation → citation formatting; **retrieval confidence scoring** (`RetrievalValidatorService`: top cosine score > 0.85 and ≥ 3 chunks → HIGH, > 0.70 and ≥ 2 → MEDIUM, otherwise LOW) which changes both the injected system instruction and the UI badge; **token budget management** (`ContextBuilderService` caps system instructions at 300, history at 800 and retrieved chunks at 2,500 tokens using a 4-chars-per-token estimator, dropping items tail-first to prevent silent context overflow); **query rewriting** (LLM call at temp 0.2 resolves pronouns/ambiguity from history into a self-contained search query, with automatic degraded passthrough if the call fails); source attribution with per-source similarity scores and chunk-level preview; drag-and-drop document upload (PDF via server-side `pdf-parse` extraction, Markdown/text read client-side) with a five-stage ingestion progress bar; document list with delete (cascades to all chunks); chat sessions with history reload and a Recents sidebar; metrics dashboard (indexed documents, total chunks, failures, latency chart, unified activity feed).
- **Pipelines:** **Ingestion (5 steps)** — insert document row → `DocumentCleaner.cleanText()` (normalise line endings, collapse whitespace) → `TextChunker.chunk()` via LangChain `RecursiveCharacterTextSplitter` (500-char chunks, 80-char overlap, split priority `\n\n` → `\n` → space → char) → `EmbeddingsService.embedBatch()` (all chunks in one batched OpenAI call) → bulk insert into `document_chunks`. **RAG query (9 steps)** — `QueryRewriterService` → `EmbeddingsService.embed()` → `VectorRetrieverService` (Supabase RPC `match_documents()`, cosine `<=>` ordering, optional `source_type` filter) → `RetrievalValidatorService` → `ContextBuilderService` → `PromptBuilderService` → `LlmService.chat()` (GPT-4o-mini, temp 0.3) → `CitationService.formatCitations()` (dedupe by document name) → response `{ answer, sources, tokens_used, retrieval_confidence, metrics, latency_ms }`.
- **Database schema (Supabase/PostgreSQL, 5 migrations):** `documents` (UUID pk, content, `source_type` CHECK in pdf/markdown/slack/github, JSONB metadata), `document_chunks` (`embedding vector(1536)`, chunk_index, JSONB metadata, cascade delete on document), HNSW index `USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64)`, `match_documents(query_embedding, match_count, filter)` PL/pgSQL similarity-search function returning `1 - (embedding <=> query)` as similarity, plus `chat_sessions` and `messages` (role CHECK, sources JSONB, tokens_used).
- **API:** `POST /ingestion/upload` (+ `/ingestion/process`), `POST /chat`, `GET /chat/sessions`, `GET|POST /documents`, `GET /documents/:id`, `DELETE /documents/:id` (204), and a Next.js `POST /api/upload-pdf` multipart proxy route.
- **Architecture:** monorepo with a NestJS backend and a Next.js frontend; **layered infrastructure** — `LlmService` and `EmbeddingsService` sit behind provider interfaces, so swapping OpenAI for another provider is a new `implements ILLMProvider` class with zero changes to pipeline or business modules; modules split into `infrastructure/` (embeddings, llm + TokenEstimator, supabase, langchain prompts & splitters) and `modules/` (ingestion pipeline, rag pipeline + strategies, chat, documents); the Next.js API routes act as a thin proxy that keeps the backend URL server-side and sidesteps CORS; frontend built from custom hooks (`useChat` with optimistic UI, streaming simulation and session persistence; `useDocuments`; `useSessions`) with shared TypeScript types mirroring backend DTOs. **Testing:** Jest unit tests cover `CitationService`, `ContextBuilderService`, `RetrievalValidatorService`, `VectorRetrieverService` and `TokenEstimatorService`, plus coverage and E2E scripts. A 15-document demo dataset (fictional SaaS "TechNova Solutions") with curated single- and cross-document test questions ships in `scripts/test-data/`.
